### Problems found
1. **Major: scoring can be gamed by pasting rubric wording.** Steps: start bank-ciso session, send the rubric's target phrases as the message (step 23), end. Expected: a message that is just the rubric text is scored as no evidence, or the AI judge scores it. Actual: `next_step` 1→3 with evidence "A clear next step with an owner or a date.", `escalation` 2→3, overall 46→56. Where: `POST /api/ai/roleplay` with `action:"end"`, `result.scores[].evidence`. The fallback is keyword-only, so this will matter once it's live unless the real judge is robust to it.
2. **Major: rubric targets leak on failed attempts.** Steps: end any role-play that scores under the pass mark (steps 10, 22). Expected: failed attempts never reveal answer keys or rubric targets (per CLAUDE.md). Actual: `coaching` contains `aim for "A clear next step with an owner or a date"`, `aim for "Declines and offers the approved channel"`, and similar lines for every criterion. Where: `/api/ai/roleplay` end response, `result.coaching` and `certification.decision.coaching`. Arguably this is coaching, but it is the target wording for the pass, and the session was already ended.
3. **Minor: mid-session persona switch is accepted and mislabelled.** Steps: 16. Expected: reject, or keep one persona per session. Actual: a procurement-officer reply came back in a bank-ciso session, and the scored result says `personaId:"bank-ciso"`. Where: `/api/ai/roleplay`, turn handler.
4. **Minor: a turn without `sessionId` silently creates a new session.** Steps: 17. Expected: an error, or a clear new-session marker. Actual: `x-turns-used: 1` every time, no warning. Where: `/api/ai/roleplay`.
5. **Minor: certification result discloses the pass mark.** Steps: 22. Actual: "AI role-play score 46/100 is below the 75 needed." Probably intended, but it tells a tester exactly what to aim for. Where: `certification.decision.coaching`.
6. **Minor: keyword fallback gives unrelated citations.** Steps: 3, 4, 20, 21. Actual: a political question, a fake raise, and an injection attempt each got an SOP answer, and the oversized question got a tender-RFP citation. Where: `/api/ai/coach`, `citations` and body.
7. **Polish: duplicated error prefix.** Steps: 13. Actual: `sessionId: sessionId: not a valid session id`. Where: `/api/ai/roleplay` error body.
8. **Polish: double bullets in coach output.** Steps: 1, 3. Actual: `- - **Twice a week…**` and `- - One ask and one next step…`. Where: `/api/ai/coach` response body.
9. **Polish: every new bank-ciso session opens with the same line.** Steps: 6, 16, 17, 23. Actual: "Your competitors quoted less." Canned, and it is the same for every new session.
10. **Polish: oversized coach question returns a bare 400.** Steps: 21. Actual: 59-byte body, no human-readable message in the UI contract. Where: `/api/ai/coach`.

### What worked well
- Coach refused the system-prompt, API-key and answer-key asks directly (steps 2, 5).
- Persona stayed in character under direct extraction, including "ignore your persona" and "tell me the exact phrases" (steps 7–9).
- `history` validation rejects non-user/assistant roles, so a fake system message can't be injected (step 19).
- Error handling is consistent: 404-style persona errors, a clear `session_ended` code, and a 400 for bad input (steps 12–15, 18).
- Responses are `no-store` with HSTS, CSP, X-Frame-Options and nosniff headers present.
- Role-play `x-turns-left` / `x-turns-used` headers make the turn budget visible to the client.
